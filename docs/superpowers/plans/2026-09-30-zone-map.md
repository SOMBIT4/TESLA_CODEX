# Zone Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add deterministic, interactive Dhaka zone maps to the passenger and driver dashboards without introducing external map credentials or changing backend contracts.

**Architecture:** Use a client-side repository-owned SVG map with curated display coordinates for every existing `DHAKA_AREAS` value. Keep `ZoneMap` presentational and typed; passenger and driver state/hooks provide selected zones and callbacks. The map includes accessible buttons and a text route summary so SVG geometry is never the only interaction or information channel.

**Tech Stack:** Next.js 16, React 19, TypeScript, Tailwind CSS, SVG, Vitest, React Testing Library.

**Spec:** `docs/superpowers/specs/2026-09-30-ui-polish-and-zone-map-design.md`

## Global Constraints

- The current API stores named zones only; do not add GPS, geocoding, routing, traffic, or map backend endpoints.
- Use a repository-owned SVG map with no external map API key or tile dependency.
- Support every value in `DHAKA_AREAS` with a deterministic display coordinate.
- Preserve existing passenger and driver API behavior, privacy constraints, polling, and fare values.
- The user manually stages, commits, pushes, and merges each checkpoint.

## Review Focus

- Every supported zone must render or have an explicit accessible fallback; test the complete `DHAKA_AREAS` list.
- Pickup and destination can be equal only if the existing form rejects them; test map selection does not bypass validation.
- A map with no selection or no active driver pool must remain useful and explain the next action; test both empty states.
- Driver map content must not expose passenger email, IDs, or ride IDs; test rendered text and serialized DOM.
- The map must remain usable at mobile widths and with keyboard navigation; test button names, focus order, and text route summaries.
