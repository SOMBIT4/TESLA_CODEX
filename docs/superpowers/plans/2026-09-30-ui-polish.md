# UI Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Refresh the Dhaka Tesla Pool web experience with a distinctive, colorful, accessible visual system, redesigned authentication pages, English/Bangla localization, and clearer passenger and driver workspaces without changing API behavior.

**Architecture:** Keep the existing Next.js App Router, Tailwind CSS, and repository-owned shadcn/ui-style primitives. Add a small client-side locale provider and typed message dictionary at the web boundary; API modules and domain types remain locale-neutral. Build the visual system from shared tokens and focused components so passenger, driver, and auth screens share a coherent product language without becoming identical templates.

**Tech Stack:** Next.js 16, React 19, TypeScript, Tailwind CSS, existing shadcn/ui-style primitives, Vitest, React Testing Library.

**Spec:** `docs/superpowers/specs/2026-09-30-ui-polish-and-zone-map-design.md`

## Global Constraints

- Use an original Dhaka Tesla Pool identity; do not use Tesla logos, wordmarks, or copied brand assets.
- Support English (`en`) and Bangla (`bn`), with English as the initial default.
- Preserve secure HttpOnly-cookie authentication and all existing API contracts.
- Keep the visual system colorful and polished but purposeful, with real product content and restrained decorative effects.
- Keep map work out of this branch; interactive zone maps belong to `feature/zone-map` after this branch merges.
- The user manually stages, commits, pushes, and merges each checkpoint.

## Review Focus

- First client render before the saved locale loads must not cause a hydration mismatch; test the stable English render and post-hydration switch.
- Bangla copy must fit labels, buttons, badges, and narrow mobile cards without clipping; test the longest auth and ride actions.
- Pending, error, empty, and unauthenticated states must remain usable after layout changes; test each existing role flow.
- Color must not be the only status signal; test visible status text and accessible names for online, waiting, active, completed, and error states.
- Auth and dashboard redesigns must not leak identities or change role redirects; test existing privacy assertions and driver/passenger destinations. The approved product name may contain “Tesla”, but no Tesla logo asset, external wordmark, or copied brand asset may appear.
