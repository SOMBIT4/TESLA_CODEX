# Zone Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Leaflet/OpenStreetMap map layer to the passenger, driver, and authentication experiences while preserving current API, fare, database, and ride behavior.

**Architecture:** A client-only wrapper dynamically loads one imperative Leaflet map instance per mounted component. Zone coordinates are presentation metadata keyed to the backend's canonical nine zones; passenger and driver integrations only adapt existing state and API responses into markers. A local map error boundary and tile fallbacks isolate all map failures from the surrounding product flows.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, Leaflet, OpenStreetMap raster tiles, Vitest, React Testing Library, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-10-02-zone-map-design.md`

## Global Constraints

- The backend export `apps/api/src/modules/fares/fare-rules.ts::DHAKA_AREAS` remains the canonical zone list; the frontend list and coordinate keys must match it exactly.
- All nine coordinates must be within latitude `23.65`-`23.95` and longitude `90.25`-`90.55`; the initial view fits all nine zones.
- Do not change backend code, endpoints, response shapes, fare logic, database schema, or ride rules.
- The passenger form sends existing zone values only; fare remains sourced from the existing API and Banani to Mohakhali remains 86.00 Tk solo.
- Create each Leaflet map once; update existing markers only when their data changes; call `fitBounds` initially and later only when the distinct set of displayed zones changes.
- Group driver members by destination zone and show every member name and seat count in that zone's single marker.
- Decorative maps disable controls, keyboard handling, and interactions; use `pointer-events: none`, a readability overlay, and visible attribution outside the `aria-hidden` canvas.
- A passenger map is read-only whenever the existing request form is disabled.
- A tile error or map startup crash must not break passenger forms, driver actions, or login/registration.
- `NEXT_PUBLIC_MAP_TILE_URL` is public build-time configuration; Docker builds must receive it, and changing it on the deployment host requires rebuilding the web image.
- Complete checkpoints in this order and stop after each for the project owner to stage, commit, and push manually: shared map and coordinates; passenger; driver; login/register.

## Review Focus

- Missing, extra, out-of-order, or out-of-bounds zones: Task 1 compares map and frontend keys to the backend export and checks all nine coordinates.
- Identical five-second driver polls: Task 3 asserts the Leaflet map and markers are reused and `fitBounds` is not called again.
- Multiple passengers sharing one destination, or a dropped-off member absent from the active response: Task 3 verifies one grouped marker and no synthetic done marker.
- An active ride or pending passenger request action: Task 2 verifies the map cannot change the disabled form or trigger another estimate.
- Tile failure or startup crash in any map context, including decorative accessibility: Tasks 1, 2, 3, and 4 verify local fallbacks and usable surrounding controls.

### Task 1: Shared Leaflet map and zone coordinates

**Files:** See the shared checkpoint list above.

**Interfaces:**

- Consumes: backend `DHAKA_AREAS` for test-time coverage comparison; frontend `DhakaArea` for web-facing types.
- Produces: `ZONE_COORDINATES: Readonly<Record<DhakaArea, ZoneCoordinate>>`, `DHAKA_QA_BOUNDS`, `ZoneMap`, `ZoneMapMarker`, and an isolated map fallback.
- `ZoneCoordinate` is `{ latitude: number; longitude: number }`.
- `ZoneMapMarker` is `{ id: string; zone: DhakaArea; role: "zone" | "pickup" | "destination"; members?: readonly { passengerName: string; seats: number }[] }`.
- `ZoneMap` accepts `{ mode: "selectable" | "pool" | "decorative"; markers: readonly ZoneMapMarker[]; disabled?: boolean; onZoneSelect?: (zone: DhakaArea) => void; className?: string }`.

Import Leaflet CSS through `apps/web/src/app/globals.css`. Add English and Bangla messages for pickup/destination selection, map fallback, marker labels, and map accessibility labels.

- [ ] **Step 2: Write failing coordinate, map lifecycle, and error-boundary tests**

  In `zone-map.test.tsx`, mock Leaflet and assert that mount creates one map, the initial `fitBounds` includes all nine zones, large circle markers are used, and an identical-content rerender creates no new markers and does not call `fitBounds` again. Assert that a changed displayed-zone set updates bounds once, while changed marker labels with an unchanged zone set update labels without resetting the view. Verify tile-load failure renders the map fallback.

  In `zone-map.test.tsx`, make the mocked `L.map()` throw during initialization and assert the map component shows its local fallback.
